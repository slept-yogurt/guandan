# 掼蛋（Guandan）网页游戏

一个**服务端权威**的掼蛋网页游戏：网页前端 + Node.js + WebSocket，零第三方运行时依赖。
支持 **1–4 人联机**，人数不足时由 **NPC 自动补位**到 4 个座位。发牌、同步、规则判定全部在服务端完成，前端只负责渲染和发送操作意图。

```
浏览器（public/）  ──HTTP──▶  静态资源
        │
        └──WebSocket(/ws)──▶  server/  ──▶  权威对局状态机
```

---

## 快速开始

```bash
# 需要 Node.js >= 18
node server/index.js
# 或
npm start
```

启动后终端会打印本机、局域网、虚拟网卡三类地址：

```
  掼蛋服务端已启动（0.0.0.0:8790）
    本机访问：http://127.0.0.1:8790
    局域网访问（同一 WiFi / 网线下用手机或另一台电脑打开）：
      http://192.168.x.x:8790   [WLAN]
```

- **单人试玩**：浏览器打开 `http://127.0.0.1:8790`，在大厅点「单人开局」，其余 3 个座位由 NPC 补上。
- **多人联机**：同一 WiFi 下，让朋友打开上面那条局域网地址（`192.168.x.x:8790`），各自进入同一房间即可。谁先进谁补 NPC，真人坐满后 NPC 自动让位。

### 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8790` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址（`0.0.0.0` 才能被局域网访问） |
| `TRUST_PROXY` | 关 | 设为 `1` 时信任 `X-Forwarded-For`（仅反代后面才开） |
| `WS_DISCONNECT_GRACE` | `45000` | 掉线后座位保留（托管）的宽限毫秒数 |
| `NPC_DELAY` | `800` | NPC / 托管座位每步行动的间隔毫秒数（调小可加速） |
| `ROUND_DELAY` | `2200` | 一局结束后停顿多久再开下一局 |

> 把 `NPC_DELAY` / `ROUND_DELAY` 设为 `0` 能让整局跑到飞快，测试就是这么跑的。

```bash
PORT=9000 NPC_DELAY=300 node server/index.js
```

### ⚠️ 改了 `server/` 下的代码，必须重启服务端进程

服务端是**常驻进程**，而 `public/` 下的 HTML / JS / CSS 是每次请求从磁盘读的。
所以「改了后端没重启」的症状非常迷惑：**界面是新的、行为是旧的**——
你会看到托管按钮、观战入口、起始级牌下拉框，但点下去**毫无反应，也不报错**
（旧服务端收到不认识的消息类型会直接 `default: return`）。

为此加了一道**协议版本握手**：

- 服务端在 `welcome` 里带 `protocol`（见 `server/version.js`），启动横幅也会打印
  `协议版本 vN · 启动于 …`（N 为当前协议号，现为 **v4**）；
- 前端版本对不上时，会在页面底部挂一条**红色横幅**，明确告诉你"请重启服务端进程"；
- `http://127.0.0.1:8790/healthz` 也会返回 `protocol` 和 `startedAt`，方便确认在跑的是哪份代码。

**不确定自己连的是不是新代码？跑这个（打的是正在运行的那个进程，不是内存里 new 出来的）：**

```bash
npm run smoke          # 默认 http://127.0.0.1:8790
npm run smoke -- http://<你的局域网IP>:8790   # 从另一台机器/手机打过来测
```

它会先看 `/healthz` 的 `protocol`，对不上就**直接判定"跑的是旧代码"并打印重启命令**，
后面的功能检查不再执行；对得上才拿真实 WebSocket 走一遍曾经"静默失灵"的功能
（起始级牌 / 人工托管 / 换浏览器观战），共 23 项。

> 为什么要单独搞一个：单元测试和 e2e 都是**自己起服务**，永远跑最新代码，
> 所以**测不出"改了没重启"**这个问题 —— 而这恰恰是玩家实际遇到的那个。

端口被占用时启动会直接失败并打印杀进程的命令（**Git Bash 的 `pkill` 杀不掉原生 Windows 进程**）：

```powershell
Get-NetTCPConnection -LocalPort 8790 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

## 玩法与规则

两副牌共 **108 张**，四人两两一队：**座位 0/2 为 A 队，1/3 为 B 队**。每人 **27 张**。

### 级牌与逢人配

- 默认从 **2** 打起（建房时可选任意起始级牌），双方各自记级；当前「打几」= 上一局赢家一方的级牌。
- **级牌**在比较时被抬到仅次于大小王的位置。
- **红桃级牌 = 逢人配**：万能牌，可当除大小王外的任意牌使用（拼牌型时自动补缺口）。

### 牌型

| 牌型 | 说明 |
| --- | --- |
| 单张 single | 1 张 |
| 对子 pair | 2 张同点 |
| 三张 triple | 3 张同点 |
| 三带二 triplePair | 三张 + 一对 |
| 顺子 straight | 5 张连续单牌，**A 可作 1**（如 A2345） |
| 连对 pairChain | 3 对连续（如 334455） |
| 钢板 steelPlate | 2 个连续三张（如 333444） |
| 炸弹 bomb | 4 张及以上同点 |
| 同花顺 straightFlush | 同花色的 5 张顺子 |
| 四大天王 jokerBomb | 两张大王 + 两张小王（最大） |

### 大小比较

- 普通牌型只能**同类型、同张数**比大小。
- 炸弹压制所有非炸弹牌型；炸弹之间按等级：
  **4 张炸 < 5 张炸 < 同花顺 < 6 张炸 < 7 张炸 < … < 四大天王**（同等级炸弹再比点数）。

### 出牌流程

- 一轮中领出者先出，其余人依次**跟牌**（出更大的同型牌）或**不要**。
- 连续 3 家不要，则由最后出牌者重新领出。
- **接风**：若某人出完手中所有牌、且其余各家全部不要，则由其**对家**接手出牌。

### 名次与升级

一局按出完牌的先后记名次（头游 / 二游 / 三游 / 末游）：

| 情况 | 升级 |
| --- | --- |
| 头游 + 二游同队（双下） | **+3** |
| 头游 + 三游同队 | **+2** |
| 头游 + 末游同队 | **+1** |

**打到 A 并在 A 局获胜，才赢下整场比赛。**

### 进贡 / 还贡 / 抗贡

每局开始前，上一局的**末游**向**头游**进贡：

- 进贡：末游交出手中**最大的一张牌**（红桃级牌除外）。
- 还贡：头游回赠一张**不大于 10** 的牌（逢人配不能用来还贡）。
- **抗贡**：若进贡一方手握**两张大王**，则可抗贡，本局免进贡。

## 界面

- **字号缩放**：大厅和牌桌都有「⚙ 设置」入口。面板里一个滑动条控制「界面与牌面大小」（80%–160%），
  牌面尺寸与所有文字**等比缩放**（`style.css` 里所有尺寸都写成 `calc(Npx * var(--fs))`，滑块只改 `:root` 上的 `--fs`）。
  设置存在 `localStorage`，刷新后仍然生效。
- **手牌排序**：设置面板里的勾选框切换「从小到大 / 从大到小」。
  **默认不勾选 = 从小到大**；勾上才是大牌在左。
  前端用和服务端 `cards.js` 里 `orderOf()` 完全一致的比较规则自己重排，所以两个方向严格互为逆序
  （直接 `.reverse()` 做不到 —— 花色、同点不同副的次序都会错）。
- **提示音**：轮到**你**出牌时响两声上行短音（WebAudio 现场合成，不加载任何音频文件）。牌桌右上角有「🔊 提示音」开关，状态记在 `localStorage`。
  > 浏览器要求音频必须由用户手势解锁，所以第一次点击页面时才会真正创建 AudioContext。
- **对局记录**：每条记录都带 `时:分:秒` 时间戳和局号，涵盖每局开局、每次出牌/不要、接风、名次、升级、进贡/还贡/抗贡、以及「某人离开由 NPC 接管」。服务端每局最多保留 1000 条、下发最后 300 条；前端只追加新增的那几条，不会每来一条就重建整个列表。
- **顶部横幅**：显示「第 N 局 / 打 X / 房间号」和两队级牌。房间号那个 pill 点一下即复制。
- **退出 vs 掉线**（两个概念不能混）：
  - **掉线**（关标签页 / 断网）→ 座位保留 + 宽限期托管，带 token 重连可无缝接回。
  - **主动退出** → 座位当场转成 NPC 托管，对局继续，剩下的玩家不用等；连接**保持可用**，人回到大厅还能立刻创建 / 加入 / 匹配。

### 建房选项

- **起始级牌**：创建房间时用下拉框选 2~10 / J / Q / K / A（默认 2），本场就从这一级打起。
  单人开局沿用同一个下拉框。服务端不信任客户端传值，越界一律夹回 2。
- **允许观战**：勾上之后，这个房间才会出现在大厅房间列表的「观战」按钮里。

### 观战

- 建房时勾了「允许观战」的房间，大厅列表里会多一个「观战」按钮（并标出当前观战人数）。
- 进入观战后必须**选一位玩家**才能看牌，**选定后不可更改**（想换只能退出观战重新进来）。
- 观战者不占座位（`seat = -1`），看到的是被观战者的手牌；出牌 / 不要 / 提示 / 托管全部不可用，服务端也会拒绝。
- 观战者同样享受 token 续连：刷新页面后还是看原来那位。
- **房间没了会被自动送回大厅**：房主退出后房间没人、或房间闲置被回收时，服务端只给观战者发一条
  房间列表消息（不发对局消息）。前端必须据此把自己踢回大厅 —— 否则观战者会永远卡在一个
  已经不存在房间的画面上（数据是旧的、按钮点了没用、只能刷新）。这条有专门的回归断言。

### 人工托管

- 牌桌右上角的「🙋 托管」把座位交给 NPC AI 代打，随时点「🤖 取消托管」拿回控制权。
- 托管意愿记在 `Game.seats[i].manualAuto`，和「掉线托管」(`auto`) 分开存：
  刷新续连会清掉掉线标记，但**不会**清掉玩家自己勾的托管。

## 设计与加固要点

- **服务端权威**：`viewFor(seat)` 只把本人手牌下发，其他座位仅给张数；出牌合法性由服务端 `rules.validate()` 判定，前端无法伪造。
- **NPC 与托管同构**：NPC 座位、掉线托管座位、玩家主动托管座位都走同一条 `stepAuto()` 路径，由房间定时器 `_pump()` 驱动。
  `isAuto(seat) = isNPC || auto || manualAuto` —— 三者语义不同：`isNPC` 是座位属性，`auto` 是掉线这类临时状态（续连即清），`manualAuto` 是玩家的明确意愿（续连保留）。
- **观战者走独立的成员名单**：`Room.spectators` 和 `Room.seats` 分开。广播时两边都要发，但观战者拿的是 `viewFor(watchSeat)`；
  `Room.humans()` 不含观战者，所以只有观战者的房间照样会被 GC 回收，不会留下僵尸房间。
  所有会改对局状态的协议（`play` / `pass` / `return` / `auto` / `again`）都先用 `client.seat < 0` 把观战者挡在门外。
- **掉线宽限 + 续连**：token 存 `sessionStorage`，重连走 `?resume=<token>`，握手阶段即识别，座位保留、宽限期内由 NPC 托管。宽限期在**对局中**保留座位，非对局中则释放座位并转移房主，避免僵尸座位堆积。
  - **token 标识的是「会话」，不是「连接」**：同一个 token 再来就把旧连接顶掉。否则刷新页面时新旧连接一旦错序到达（新连接先到、旧连接的 `close` 还没处理），旧会话会被当成全新客户端，座位随后被 NPC 接管。
  - 续连时**校验座位归属**：只有座位还在、且仍是这个客户端的，才算续连成功，绝不把别人的座位抢过来。
  - **被顶号用关闭码 `4001` 通知客户端**（不是 `1000`）。前端收到 `4001` 就**停止自动重连**并弹一条
    「这个会话已在另一个页面打开」的提示，由用户决定关掉哪个页面或点「在此页面继续」抢回来。
    为什么必须区分：浏览器「复制标签页」会把 `sessionStorage` 一起复制，两个页面共用一个 token。
    若被顶号也当普通断线去重连，两边就会互相抢 token、**无限顶号**，谁也连不上。
  - ⚠️ `_resume` 里**必须先换 `client.conn`、再关旧连接**。自写的 WS 实现里 `close()` 会**同步**
    `emit('close')`，顺序写反会同步重入 `_onDisconnect`：不在房间里时直接把会话从
    `clients`/`byToken` 里删掉（这个页面从此收不到大厅房间列表更新、刷新还会拿到全新会话），
    在房间里时会顺手给座位打上掉线托管。有专门的回归断言盯着这两条。
- **「我是几号位」由服务端告知**：`viewFor(seat)` 里带 `you`，房间视图里也带 `you`。前端不再靠昵称匹配认座位（昵称为空时会退化成"随便挑一个非 NPC 座位"，多人房里会认错人）。
- **WebSocket 协议加固**：客户端帧必须掩码、RSV 必须为 0、控制帧不可分片且 ≤125 字节、分片累计总量上限、连接数上限。
- **双层限流**：兜底令牌桶在 `JSON.parse` **之前**挡洪泛；放大类令牌桶在解析后管广播型消息。
- **所有定时器回调都兜了异常**：`stepAuto`、`nextRound`、`expireGrace`、`gc`、心跳 —— 定时器里抛异常会直接把整个服务进程带走，一个房间出问题不该影响别的房间。
- **可复现**：`mulberry32` 种子 RNG + 注入式 `rng`，让模拟与测试可重放。
- **协议版本握手**：服务端在 `welcome` 里带 `protocol`，前端对不上就挂红色横幅。
  这是为了消灭「改了后端没重启 → 界面上有按钮但点了没反应、还不报错」这个坑 ——
  它在本项目里出现过两次，第二次是托管 / 观战 / 起始级牌三条同时失灵。
- **一个坏字段不能把整张牌桌带崩**：`renderTable()` 里 `(my + off) % 4` 在 `my = -1` 时
  等于 `-1`（JS 取模不取绝对值），`g.seats[-1]` 是 `undefined` → 整个渲染抛错。
  观战者的 `you` 恰好就是 -1，而 `Room.broadcast()` 每轮都先发房间消息再发对局消息，
  所以观战者每收一次广播就崩一次。现在 `my` 会被夹到合法范围，座位取不到也直接跳过。
- **颜色不要靠继承**：牌面用的是白底，而牌桌中央区 `.board-center` 的 `color` 是近白色。
  `.mini.red` / `.mini.black` 按花色显式给色，大小王走的是 `.joker.big/.small` 分支，
  拿不到那两个类 → 只能继承 → 白字白底完全看不见。凡是"卡片上的文字"，颜色都要写死。
  这条用**对比度**（≥ 3:1）而不是"颜色不相等"来断言 —— 后者抓不到"深灰 vs 更深灰"。

## 安全提醒

局域网模式跑的是**明文 HTTP**，仅在自家 / 信任的网络中使用。若要暴露到公网，请自行加一层 TLS（反向代理）并设置 `TRUST_PROXY=1`。
